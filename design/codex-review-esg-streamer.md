### 1. 與全站風格不一致之處

- 電子證書使用漸層：

- 語言代碼色塊過度飽和：
  `.lang .fl` 的背景由 JS 內嵌色彩控制，例如 `#d33`、`#2563eb`、`#e11`、`#c00`、`#1e40af`。  
  紅藍色塊同時出現，視覺接近 SaaS 語言選單，沒有低飽和文青感。

- 藍色膠囊標籤偏產品後台風：
  `.badge { color:#fff; background:var(--accent); border-radius:999px }`（第 36–39 行）。  
  全站雖有膠囊標籤，但這裡的純藍底白字面積較重，與奶茶／鼠尾草平塗的柔和層次不完全相符。

- 元件造型過於一致、缺少編輯感：
  `.card`、`.lang`、`.opt`、`.kpi`、`.bars` 全部是規整圓角框。雖然 token 正確，組合起來仍像標準 dashboard，而不是帶襯線、留白與局部像素點綴的作品集案例。

- 陰影使用略多：
  `.card`、`.btn`、`.cert` 都用 `var(--shadow-card)`。單獨看不重，但同一流程重複套用會降低紙本平塗感。

- 首屏沒有視覺主角：
  hero 只有 eyebrow、標題、說明和 context line。與主站的 voxel isometric 視覺系統沒有建立聯繫。

- 手機 hero 直接貼齊螢幕：
  共用 CSS 的 `.wrap { padding:0 var(--space-3) }` 被後面的 `.hero { padding:var(--space-7) 0 var(--space-6) }` 覆蓋。因為同一元素同時是 `.hero.wrap`，手機截圖中標題與文字從 x=0 開始，和下方 24px 邊距明顯斷裂。

### 2. 最值得調整的 5 項

1. 修正手機 hero 水平留白  
   保留 `.wrap` 的左右 padding，只設定 hero 的 `padding-top`、`padding-bottom`，或明確寫成 `padding:... var(--space-3)`。這是最直接的版面瑕疵，也會影響閱讀舒適度與整站一致性。

2. 加入一張 ESG 專屬 voxel hero  
   桌機可改成文字／圖像雙欄；手機則將圖放在標題說明之後。視覺能立即把「多語培訓、認證、企業儀表板」串成作品概念，而不是一進頁面就看到大量文字。

3. 統一語言選擇器的色盤  
   不以國旗式紅藍區分語言。五個 `.fl` 可統一使用鼠尾草、奶茶、淡藍、灰藍等低飽和底色，文字用墨灰；選取狀態再使用品牌藍框線。語言差異由代碼與名稱承擔，不必由高飽和顏色承擔。

4. 重做證書視覺  
   移除 `.cert` 漸層，改成固定暖紙白或淺奶茶色；金色雙框改為墨灰細框＋單一琥珀色印章。既保留「正式證書」語意，也符合規範中的平塗與單一琥珀重點。

5. 降低後台元件感  
   減少膠囊、陰影與層層卡片：`.badge` 可改為小型像素章或淡色標籤；`.card` 保留主容器即可，內部 `.lang`、`.kpi`、`.bars` 以細線、底色分區和排版層級取代每個區塊都像獨立卡片。

### 3. 適合加入生成圖的位置

- Hero 主圖：最適合使用 voxel。  
  場景可是一塊漂浮方形底座，上面有五位簡化 voxel 學員圍著培訓螢幕；螢幕以五個無文字色塊表示多語內容，旁邊有證書、QR 方格與企業儀表板。主色品牌藍，家具用淺木色，只以一個琥珀色小印章標記認證完成。

- 課程完成／發證畫面：適合小型像素插圖。  
  可用像素風證書、印章或戴安全帽的多語學員，尺寸不宜過大，作為完成回饋而非另一張 hero。

- 企業戰情室空狀態：適合小型 voxel 圖。  
  場景是一張辦公桌、簡化柱狀圖螢幕與五個學員方塊，不放任何可辨識文字。不要在初始語言卡片中塞五張生成圖，會讓操作介面太吵。

### 4. 手機版可用性問題

- Hero 無左右安全距離，是目前最明顯問題。
- hero 標題約三行、說明約五行，再加 context line，首屏資訊密度偏高；真正的「立即體驗」被推到下一屏。
- `.langgrid` 在手機仍維持兩欄。中文與 English 尚可，但 `Bahasa Indonesia`、`Tiếng Việt` 已明顯折行，使卡片高度不一致、掃讀節奏破碎。
- 語言卡片是 `<div onclick>`，不是原生 `<button>`；鍵盤操作、焦點樣式與語意化不足。
- `.lang:hover` 只有 hover 回饋，手機沒有清楚的 pressed／selected 狀態。
- 上方「培訓認證／企業戰情室」按鈕尺寸偏小，雖可點擊，但不算理想的 44px 觸控目標。
- 若切換至 dashboard，三欄 `.dash` 沒有手機斷點，KPI 文字很容易擁擠。
- `.bar .lb { width:96px }` 在窄螢幕會壓縮進度條；較長的語言名稱或證書編號也可能溢出。
- 課程頁的標題與語音按鈕用行內 flex 並排，長語言標題在手機上可能與按鈕互相擠壓。

## Streamer AI

原始碼：[demos/streamer_ai/index.html](/C:/Users/USER/fde_html_learning-main/fde_html_learning-main/demos/streamer_ai/index.html)

### 1. 與全站風格不一致之處

- 整套色彩是高飽和霓虹：
  `:root { --cyan:#25e0e6; --mag:#b14dff }`（第 16 行）。  
  青紫霓虹與全站的鼠尾草、奶茶、暖白、墨灰完全不同。

- 大量使用漸層：
  `.demo-stage` 的雙重 `radial-gradient`、`.phone` 的深色 `linear-gradient`、`.top`、`.av`、`.me`、`.send` 都有漸層。這直接違反「無漸層、平塗」方向。

- 光暈與厚重陰影過多：
  `.phone` 使用 `0 30px 80px rgba(0,0,0,.6)`；`.av`、`.live`、`.me`、`.send` 都有 neon glow。效果更像遊戲直播 overlay，而不是低飽和作品集。

- 永久深色聊天框與網站主題割裂：
  `.phone`、`.foot input`、訊息內容大量硬編碼深藍與淺字，沒有使用 `--surface-*`／`--ink-*` token。切換網站深淺色時，聊天介面基本不變。

- 圓角語言過度膨脹：
  `.phone` 24px、訊息 15px、chips 20px、輸入框 22px、send 圓形，整體接近手機 App 或 Discord bot，而非全站較克制的 4px／8px 圓角體系。

- 字體層級沒有延續襯線標題：
  頁面只有 eyebrow 和一段說明，沒有正式 `h1`／`h2`；聊天頭像名稱 `.nm` 使用粗體 sans。結果缺少全站很重要的襯線標題節奏。

- 頭像只是漸層字母方塊：
  `.av` 是 `DC`＋霓虹色塊，既沒有像素風，也沒有主站 voxel 語彙。

- 桌機比例不佳：
  `.phone { height:min(780px,86vh) }` 加上 `.demo-stage { min-height:72vh }`，造成非常高、內容卻集中在上方的黑色空腔。截圖裡中段約半個畫面是沒有資訊的深色區域。

- 名稱與說明本身承認「功能內容維持原樣，僅統一外觀」，但目前實際外觀並未統一；這會讓文字承諾和視覺結果互相矛盾。

### 2. 最值得調整的 5 項

1. 移除霓虹色盤、漸層與 glow  
   將 `--cyan`、`--mag` 改為全站 token 或頁面專用低飽和色：暖白背景、鼠尾草 header、奶茶 chips、墨灰文字、品牌藍作唯一主要互動色。所有 `linear-gradient`／`radial-gradient` 改成純色；陰影改用 `var(--shadow-card)`。

2. 讓聊天框成為「作品集中的產品樣機」，而不是黑色電競裝置  
   `.phone` 改成暖白或淡灰紙面卡片，8–12px 圓角、細邊框；聊天背景可用極淡鼠尾草色。bot 訊息白色、使用者訊息品牌淡藍，不需要持續深色模式。深色主題再由共用 token 自動轉換。

3. 補齊頁面標題與敘事層級  
   在 eyebrow 後加入襯線 `h1`，例如「直播主官方 AI 小助手」，下方再放精簡描述。桌機可採左側作品說明、右側聊天樣機；目前「一句說明＋中央手機」比較像孤立的 prototype。

4. 重新設定聊天框高度  
   不要固定接近 780px。桌機初始狀態約 560–620px 已足夠展示互動；或根據內容使用 `clamp()`。聊天內容增加時再由 `.chat` 捲動。這能消除截圖中大片無效深色空間。

5. 用像素角色取代 `DC` 漸層頭像  
   參考 `ai-service` 的像素貓頭像做法：`image-rendering:pixelated`，使用低飽和像素主播角色。`LIVE` 可以保留，但改為小型琥珀或低飽和磚紅標記，避免螢光紅光暈。

### 3. 適合加入生成圖的位置

- 聊天頭像：最適合像素圖。  
  生成一個簡化、無寫實五官的像素主播角色，例如墨灰頭髮、鼠尾草耳機、奶茶色上衣；尺寸小、輪廓清楚，與 `ai-service` 的像素 avatar 形成同系列。

- 桌機版樣機旁的情境圖：適合 voxel。  
  場景是一塊浮動方形底座，上面有直播桌、麥克風、攝影機、螢幕，以及一個代表 AI 助手的小型立方機器人。螢幕只顯示色塊，不能放帳號、文字或 logo。

- 對話空狀態：適合極小像素插圖。  
  若尚未開始聊天，可在訊息區中央放像素麥克風或小機器人，開始對話後淡出。不要把完整 voxel 場景塞進聊天框，否則會搶走訊息閱讀焦點。

### 4. 手機版可用性問題

- `.phone` 使用 `height:min(780px,86vh)`，加上頁首和介紹後，輸入框通常落在首屏以下；使用者必須先捲動整頁才能開始操作。
- `86vh` 沒有考慮行動瀏覽器動態網址列與虛擬鍵盤；聚焦輸入框後可能出現樣機被裁切、頁面與內部聊天區雙重捲動。
- 聊天框本身有 `.chat { overflow-y:auto }`，外層頁面也會捲動，容易產生 nested scrolling。
- 手機 header 中名稱已折成兩行，狀態又折成兩行；再加固定寬度的語音按鈕，頭部顯得擁擠。
- `.voice` 的實際高度約 32px，低於舒適觸控尺寸。
- `.chip` 高度也偏小，四個快速選項密集排列，長文字可能形成不規則折行。
- `.msg { max-width:82% }` 配上 15px 左右 padding，在 327px 容器內中文每行可容納字數偏少，使短訊息也變得很高。
- 送出按鈕只有圖示，缺少明確 `aria-label`；語音切換雖有視覺 `.off`，但沒有 `aria-pressed` 狀態。
- 輸入列沒有處理 `env(safe-area-inset-bottom)`，在有 Home Indicator 的裝置上可能太貼近底部。
- 頁面介紹結束後立即進入大面積有色背景，手機上缺乏段落間界線；若改成暖白樣機卡＋細框，資訊結構會更清楚。
